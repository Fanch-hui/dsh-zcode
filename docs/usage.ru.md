# DSH ZCode: использование и разработка

**[简体中文](usage.md) | [English](usage.en.md) | Русский**

В этом файле собраны полные сведения об установке, использовании, CLI, headless и разработке; он не входит в пакет плагина. На странице плагина в DSH показывается краткое описание из [README.ru.md](../README.ru.md).

Плагин позволяет использовать BigModel и Z.AI Coding Plan и ZCode Start Plan в DeepSeek Harness через [TriDefender/zcode-api](https://github.com/TriDefender/zcode-api).

Плагин включает ядро прокси исходного проекта фиксированной версии `4.8.8.android`, коммит `158e7653b738cbed0996243eeabd26f816638e81`. Вход, разрешение учётных данных, эндпоинты тарифов, подпись запросов, организация системных сообщений и пересылка upstream полностью переиспользуют это ядро. Адаптер DSH отвечает за каталог моделей и преобразование сообщений и потоков; выполнение инструментов, подтверждения, сессии и субагенты — зона ответственности DSH.

## Установка и использование

Базовая версия разработки — DSH **0.2.2-rc.1**, диапазон совместимости `>=0.2.2-alpha.3 <0.3.0`, Node **24.9.0 и новее**. Десктопное приложение использует свой встроенный Node.

```bash
dsh plugin --profile desktop add dsh-zcode@0.2.1
```

Команда устанавливает плагин из [npm](https://www.npmjs.com/package/dsh-zcode). Для DSH, установленного через npm, замените профиль на `web`.

Также можно скачать `.tgz`-пакет из [GitHub Releases](https://github.com/Fanch-hui/dsh-zcode/releases) и добавить его как локальный файл через менеджер плагинов десктопного приложения или выполнить:

```bash
dsh plugin --profile desktop add ./dsh-zcode-0.2.1.tgz
```

1. Откройте «Плагины → ZCode» и выберите платформу и тариф.
2. Нажмите «Войти» и завершите авторизацию на официальной веб-странице. Существующие записи входа плагина при первом использовании разрешаются ядром прокси.
3. В переключателе моделей DSH выберите соответствующий тариф, например `ZCode · Z.AI Start Plan`.
4. Смотрите квоты на странице настроек плагина; кнопка «Обновить» запрашивает актуальные данные.

Оба тарифа используют общий веб-вход платформы. Coding Plan также принимает ключ тарифа вручную. Значения по умолчанию: параллельность 2, лимит вывода 32 000 токенов, тайм-аут запроса 300 секунд, интенсивность размышлений «Высокая».

## Модели и тарифы

| Модель | Ввод | Контекст | Максимум вывода | Интенсивность размышлений |
| --- | --- | --- | --- | --- |
| GLM-5.3 | текст | 1 000 000 | 128 000 | low / high / max |
| GLM-5.3-Flash | текст, изображения | 1 000 000 | 128 000 | low / high / max |
| GLM-5.2 | текст | 1 000 000 | 128 000 | off / high / max |
| GLM-5-Turbo | текст | 200 000 | 64 000 | выкл / вкл |

Четыре провайдера: `zcode-bigmodel`, `zcode-zai`, `zcode-bigmodel-start-plan` и `zcode-zai-start-plan`. Тариф и выбор модели определяют используемый канал; когда платформа возвращает ошибки квоты или прав, отображается соответствующее состояние.

Каталог Coding Plan предлагает GLM-5.3 и GLM-5.3-Flash; каталог Start Plan — GLM-5.3-Flash, GLM-5.2, GLM-5-Turbo и GLM-5.3. Каждая модель предоставляет свой набор интенсивностей размышлений, а настройки вывода действуют в пределах её лимитов.

Запросы квот вызывают `collectQuotaSnapshot` ядра прокси. Start Plan показывает балансовые корзины моделей, Coding Plan — окна тарифа. Запросы кэшируются на 60 секунд; ручное обновление получает свежие данные. Статистика токенов пересчитывается по методике DSH: вход, чтение кэша, запись кэша и выход.

## Статистика токенов

«Статистика токенов» на странице настроек учитывает вызовы моделей через этот плагин по провайдеру и модели: каждая строка — комбинация тарифа и модели с числом вызовов, всего токенов, входом, выходом, чтением из кэша и процентом попаданий; итоговая строка «Итого» суммируется по строкам выше. Входные токены — весь вход (вход без кэша + чтение кэша + запись кэша); всего токенов = вход + выход; процент попаданий = чтение кэша / вход × 100%. Статистика накапливается только в текущем процессе хоста, обнуляется при перезапуске плагина и не записывается на диск; отменённые или прерванные запросы без данных об использовании не учитываются. Пока страница настроек открыта, она обновляется каждые 5 секунд; можно также нажать «Обновить» для немедленного чтения.

## Локальная работа

Хост запускает отдельный дочерний процесс прокси для каждого аккаунта и тарифа; он слушает случайный порт `127.0.0.1`, каждый интерфейс защищён временным случайным ключом. Управляющие сообщения идут через IPC родитель-дитя. При смене аккаунта или деактивации плагина связанные процессы завершаются, а ожидающие запросы отменяются.

Учётные данные сохраняются службой DSH credentials в домене `llm-zcode`. Дочерний процесс прокси получает только снимок учётных данных аккаунта текущего запроса; браузерный RPC получает только публичное состояние. Идентификатор устройства — UUID, сгенерированный и сохранённый плагином. Логи прокси не попадают в сессии DSH.

Автоматическое получение тарифов, MCP-шлюз, асинхронная очередь и Responses API исходного проекта в этой интеграции отключены. Вызовы моделей следуют опубликованной конфигурации капчи платформы, где `skip_model_request` определяет, нужна ли проверка для запроса модели; при необходимости ручной проверки возвращается соответствующее уведомление.

Каждая попытка вызова модели DSH отправляет один запрос локальному прокси. Прокси сохраняет логику соединений и протокола исходного проекта; повторные попытки при временных ошибках выполняет DSH. Вызовы инструментов и их результаты проходят в исходной сессии DSH; при обрыве потока после начала вывода предлагается продолжить текущую сессию.

## CLI и headless

Терминальная команда использует то же хранилище учётных данных DSH и ядро прокси:

```bash
dsh plugin --profile web exec dsh-zcode login --platform zai
dsh plugin --profile web exec dsh-zcode status --platform zai --plan start-plan
dsh plugin --profile web exec dsh-zcode quota --platform zai --plan start-plan
dsh plugin --profile web exec dsh-zcode disconnect --platform zai
```

`--home <каталог DSH>` задаёт каталог данных DSH. Команда входа выводит официальную ссылку авторизации; для отмены нажмите Ctrl+C.

CLI и веб-интерфейс используют локаль из `ZCODE_LOCALE` (`zh` / `en` / `ru`), затем `LC_ALL` / `LC_MESSAGES` / `LANG`; браузерный интерфейс — язык браузера. По умолчанию — китайский.

Профиль DSH headless требует явно включённой службы учётных данных и модели по умолчанию:

```yaml
- id: credentials
  disabled: false
- id: agent-default-model
  config:
    provider: zcode-zai-start-plan
    model: GLM-5.3
    reasoningEffort: high
```

Сохраните конфигурацию как `zcode-headless.patch.yml`, завершите вход и выполните:

```bash
dsh headless --patch ./zcode-headless.patch.yml "ваша задача"
```

## Разработка

```bash
npm ci
npm run typecheck
npm test
npm pack
```

`vendor/zcode-api` хранит исходники прокси фиксированной версии и лицензии, `integration` содержит точку входа IPC и части совместимости с хостом, `scripts/build-proxy.mjs` собирает автономный Node-прокси. Сборка также генерирует host ESM, автономный CLI и браузерную фабрику и проверяет точки входа пакета и границы браузера.

Строки интерфейса находятся в `src/i18n`: `zh.ts` — эталон, `en.ts` и `ru.ts` обязаны покрывать те же ключи (проверяется системой типов), а `tests/i18n.test.ts` фиксирует поведение определения локали. Тесты, проверяющие китайские сообщения, явно задают `ZCODE_LOCALE=zh`.

Тесты используют синтетические учётные данные и ответы и покрывают смену аккаунтов, изоляцию процессов, обмен вызовами инструментов, отмену потоков, квоты и RPC. Действия в интерфейсе и реальные вызовы тарифов проверяются пользователем вручную.
